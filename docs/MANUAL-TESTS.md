# 实机回归清单

适用于 Smart Input 0.3.1 及后续版本。0.3.1 为工程修复版，功能与 0.3.0 一致；0.3.0 在 0.2.1 的 Visual Studio 能力之上新增 Transact-SQL 与 SSMS 支持；自动化测试（138 项）与双包结构校验已通过。**SSMS 22 已于 2026-10-07 完成首轮实机（部署、加载、菜单、状态栏、T-SQL 上下文识别，以及搜狗拼音自动 / 手动切换均通过，详见下文验证矩阵与 `docs/VALIDATION.md`）；SSMS 22 + 微软拼音以及 SSMS 18/19/20 仍需在装有对应环境的机器上按本清单实测。**

## 安装之前

1. 保存正在编辑的文件。
2. Visual Studio 建议使用实验实例或其他独立实例，不直接影响日常开发环境。
3. 当前 VSIX / SSMS 负载未签名。出现未知发布者或 SmartScreen 提示时，请先核对来源与脚本内容。
4. 实验实例会产生独立配置和缓存；扩展运行期间会改变该实例的输入态和临时光标样式。
5. 不改变系统默认输入法、微软拼音兼容模式或快捷键设置。
6. 出现问题时先点击编辑器底部的 `Smart Input` 暂停；状态栏隐藏或按钮不可用时，Visual Studio / SSMS 22 可使用 `工具 > Smart Input: 暂停自动切换`，SSMS 18-20 请直接在选项页关闭“启用自动切换”。

## SSMS 部署检查（0.3.0 新增）

1. 先运行 `.\build.ps1` 完成双包构建。
2. 完全关闭 SSMS（任务管理器确认无 `Ssms.exe`）。
3. 以管理员 PowerShell 运行对应脚本：
   - SSMS 22：`tools\Deploy-SSMS22.ps1`。
   - SSMS 18/19/20：`tools\Deploy-SSMS-Legacy.ps1`（可加 `-Version 20`）。
4. 确认脚本输出的目标目录下文件已平铺（SSMS 22 为 6 个文件含 `manifest.json`、`catalog.json`；SSMS 18-20 为 4 个文件）。
5. 启动 SSMS；若未加载，用 `Ssms.exe -log` 启动并查看 `%AppData%\Microsoft\SSMS\<版本>\ActivityLog.xml` 是否有 SmartInput / 程序集加载错误。
6. 卸载验证：`-Uninstall` 后重启 SSMS，扩展与状态栏应消失。
7. 注意不要把现代包装进 SSMS 18-20，也不要把 Legacy 包装进 SSMS 22 / Visual Studio，否则会出现“包未正确加载”。

## T-SQL / SQL 编辑器场景（0.3.0 新增）

优先打开 `samples/Contexts.sql` 逐项验证（Visual Studio SQL 编辑器与 SSMS 查询窗口都应测试）：

- 普通 `SELECT ... FROM ...`、表名 / 列名、负数 `= -1`：英文。
- `[订单表]`、`"Customer"` 等括号 / 双引号标识符，即使内部是汉字：英文。
- `[a]]b]`、`"a""b"` 转义标识符：英文；标识符内部的 `'`、`--` 不触发字符串 / 注释。
- `-- 查询用户`：进入注释即中文；注释换行写 `SELECT` 恢复英文。
- `/* 中文 */` 块注释中文；嵌套 `/* outer /* inner */ still */` 在外层闭合前都为中文，闭合后恢复英文。
- `N'已支付'`、`'查询用户'`：含汉字字符串中文；`'pending'`、空串 `''`、`'😀'`：英文。
- `'it''s ok'`、`N'数量：''两件'''` 的 `''` 转义：仍是同一字符串，按整体内容判中英文。
- 跨行字符串 `N'第一行\n第二行'`：第二行仍按字符串判断。
- 字符串内部的 `--`、`/*` 不切换为注释规则。
- 状态栏在 SQL 窗口底部出现 `Smart Input · …`；单击可暂停 / 恢复（SSMS 18-20 以此替代工具菜单命令）。
- 其余手动覆盖、组词不切换、选区不切换、切换文档、失焦恢复等通用行为，与下文 Visual Studio 场景一致，在 SQL 窗口复测一遍。

## Visual Studio 场景

- 安装 0.3.1 后重启 VS：扩展管理器显示版本为 0.3.1。
- `工具 > 选项 > Smart Input > 常规`：只显示长期设置，不显示临时暂停项。
- 修改手动覆盖光标颜色：进入手动覆盖后光标使用新颜色；退出覆盖后恢复原生光标。
- 修改状态栏文字颜色：启用自定义颜色后底部 `Smart Input` 状态按钮文字变化；关闭后跟随 VS 主题。
- 关闭“显示左下角状态栏”：状态按钮消失；`工具 > Smart Input: 暂停自动切换/恢复自动切换` 仍可操作临时暂停。
- 关闭“启用自动切换”：不读写输入法、不显示手动覆盖光标；工具菜单命令不能绕过总开关。
- 重新启动 VS：长期设置应保留；临时暂停状态不应保留。
- 第一次进入普通代码：英文；进入已有注释：中文。
- 输入 `//`、`/*` 后开始中文；`*/` 后回到代码恢复英文。
- 注释内换行（包含自动补 `*`、`///`）及单行注释结束后换行。
- `int count = 0; // 当前数量`：左右两部分分别英文/中文。
- `printf("加载成功");`：字符串内中文，引号外英文。
- 空字符串、URL、反斜线转义、C++ raw string、C# verbatim/raw/interpolated string。
- C# `$"数量：{count}"`：文字中文，表达式英文；嵌套字符串、注释分别判断。
- 注释中使用输入法实际配置的切换键切到英文并输入 TODO：显示配置的覆盖光标颜色，连续输入不抢回。Shift 仅在输入法设置中已启用时适用，也可使用 Ctrl＋空格等实际配置。
- 代码中手动切中文：显示覆盖光标颜色；再切英文恢复原色。
- Shift+字母、Shift+方向键、Ctrl+Shift 快捷键：不能仅因按 Shift 误判切换。
- 自动切换前后立即使用已配置的切换键：手动选择应保留，不应闪烁或反复抢切。
- 拼音尚未上屏、候选窗打开时：不切换；数字选词、空格上屏、Escape 取消后恢复判断。
- 鼠标移动、方向键、Home/End、点击中文段、切换文档、拆分窗口。
- 有选区、矩形选区、多光标：暂停自动判断，恢复单光标后按场景切换。
- 点击底部按钮：所有文档暂停/恢复；暂停时还原光标；再次点击恢复。
- 点击 `工具 > Smart Input: 暂停自动切换/恢复自动切换`：效果与底部按钮一致，菜单文字随状态变化。
- 焦点进入补全框、重命名框、搜索框、终端或其他软件：不得主动切换；同时观察 Windows 自身是否继承输入态。
- 主题切换、覆盖光标、失焦、关闭文档：恢复新主题的正常光标颜色，不遗留自定义装饰。
- 输入法切换失败：显示未确认，不持续重试；换区域后可以重试。
- 切换到其他输入法：不主动切回微软拼音，不尝试控制不支持的输入法。
- 搜狗拼音：进入代码、注释、字符串和失焦场景时，英文/中文状态、手动覆盖、候选窗、Escape、切换文档和切回微软拼音。
- 搜狗拼音与微软拼音共存：只控制当前活动 Profile，不主动激活或切换另一个 Profile。
- `#if` 非活动代码、复杂宏、C++ 行拼接、C# 插值格式段：记录识别偏差。
- 大文档和快速输入：不阻塞 UI；旧分析结果不能作用于新快照。
